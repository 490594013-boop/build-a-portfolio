# build-a-portfolio

> 把项目材料变成「能过面试的作品集案例」。
> 不是排版工具，是一条**先选叙事、再写文案**的流水线。

![cover](assets/cover.png)

---

## 它解决什么问题

大多数人做作品集是从"我该怎么排版"开始的，结果写出来的东西是这样：

- 罗列做了什么功能，但说不清为什么这么做
- 痛点、机会点、方案三层讲的是同一件事，读者觉得重复
- 数据漂亮，但一算就对不上
- 明明是好项目，讲出来平平无奇

**这个 skill 把顺序反过来：先决定"这个项目该怎么讲"，再动笔。**

---

## 核心设计：先给 2–4 条叙事，让作者选

同一个项目，换一种讲法就是另一份作品集。

这个 skill 拿到材料后**不会直接写文案**，而是先给出 2–4 条候选叙事：

```
【方案 A · 调研驱动型】把"用户是谁"钉死
【方案 B · 约束突破型】没有资质怎么把业务做成
【方案 C · 迭代修正型】上线一周被现实打回
```

三条方案的**开头、主角、结尾都不一样**。作者选一条，再往下排页面。

> 判断是不是"真的不同方案"：**如果两条方案的页 1 和最后一页讲的是不同的事，才算不同。**
> 换措辞、加内容、改篇幅都不算。

## 七步流程

| 步 | 目标 | 产出 |
|---|---|---|
| 0 | 收料 | 事实清单（标出必须确认的项）|
| **1** | **叙事选项** ⭐ | 2–4 条候选叙事 → 作者选一条 |
| 2 | 定逻辑 | 页面清单（每页一句话职责）|
| 3 | 定文案 | 逐页文案（方案页四段式）|
| 4 | 定配图 | 信息图 / 截图清单 + 生成提示词 |
| 5 | 定视觉 | 风格规范 + 样张 |
| 6 | 交付 | 审查 + PDF 合并压缩 |

## 叙事原型库（7 种）

| 原型 | 一句话 |
|---|---|
| 方法先行型 | 没有条件，就造方法 |
| 调研驱动型 | 先搞清楚用户到底是谁 |
| 约束突破型 | 硬约束下重新定义问题 |
| 迭代修正型 | 上线就被现实打回 |
| 数据优化型 | 把一个数字从 A 提到 B |
| 协作博弈型 | 多方目标之间找平衡 |
| 能力前瞻型 | 新技术该用在哪、不该用在哪 |

每个原型都写明了：张力来源、六段排法、最需要的素材、适合什么项目、**常见坑**。
见 [`references/narrative-archetypes.md`](references/narrative-archetypes.md)。

## 内含的三条"防翻车"机制

### ① 三层区分法

```
痛点（现象）  →  机会点（设计判断）  →  方案（具体机制）
```

**判断标准**：把机会点那句话拿到别的项目里还成立吗？成立 → 是判断；不成立 → 还是方案。

最常见的病：第 5 页的"机会点"和第 6 页的"方案"写得一模一样，读者觉得你重复讲了两遍。

### ② 数据验算

每一个百分比都要用首尾数字反推：

```
100 → 17          = 减少 83%      ✓
1,000 → 14,000    = 提升 1300%    ✓
48% → 51%         = +3pp（不是 +3%）✓
```

同时约定：大促月、业务交接、多因素叠加时，**不能简单归因于本功能** —— 这条判断本身就是加分项。

### ③ 排版一致性检查

引号是否统一、中英文空格是否一致、日期有没有漏字、括号是全角还是半角。
这些是设计作品集的"门面"，能脚本化扫描。

## 安装

这是一个 Agent Skill（`SKILL.md` + `references/` + `scripts/` 结构）。

**DeepSeek Harness**

```bash
cp -R build-a-portfolio ~/.dsh/skills/
```

**Claude Code / 其他支持 Skills 的 Runtime**

```bash
cp -R build-a-portfolio ~/.claude/skills/
```

安装后，用 `/build-a-portfolio` 或直接用自然语言描述需求即可触发。

## 脚本用法

依赖 `pypdf`（纯 Python）+ `Pillow` + 系统 `sips`（**仅 macOS**）。

```bash
python3 -m pip install --target .pylibs pypdf
export PYTHONPATH=.pylibs
```

```bash
# 1. 从导出的 SVG 提文字，并检测复制粘贴造成的重复段落
python3 scripts/extract_svg_text.py ./pages --out all-text.md --dup-only

# 2. PDF 技术审计：页面尺寸、出血、文字层、书签、体积
python3 scripts/audit_pdf.py portfolio.pdf

# 3. 合并 + 压缩 + 加书签（34MB → 6MB 的配方）
python3 scripts/build_pdf.py --in ./single-pages --out final.pdf \
    --raster 4,7,8,9,10,11,12,13 --target-mb 10 --titles titles.txt
```

> `build_pdf.py` 的思路：**纯矢量页保留矢量，截图页按原生宽度重编码**。
> 实测 1920×3917 的截图长页 6.8MB → 0.87MB，平均像素差 0.73/255。

## 适用 / 不适用

**适合**

- B 端 / C 端项目的完整案例包装
- 有调研材料、但不知道怎么组织叙事的项目
- 已有文案、需要有人挑逻辑漏洞和数据错误
- 需要把 14–20 页 SVG / Figma 稿交付成能投递的 PDF

**不适合**

- 纯视觉作品集（插画、平面），这个 skill 偏叙事逻辑
- 没有真实项目材料的「虚构案例」
- 非中文语境的作品集

## 一个诚实的提醒

这个 skill 里有一条铁律是给 AI 自己看的：

> **看不见图就不要评图。** 若当前模型无法查看图片，禁止对配色、版式下视觉结论；
> 改用文字提取和技术审计，并明确告知用户这一局限。

所以它能可靠地帮你查**逻辑、文案、数据、尺寸**，但**不能替你判断好不好看**。
